# Grocery acquisition recovery

User authorized fixes after production traces confirmed six-second acquisition timeouts and HTTP 429 responses. Development and production share the same Prej key. Keep the existing demand-driven cache and verified-offer eligibility.

1. Add a key-scoped persistent Prej cooldown in the existing Cosmos container. Use a SHA-256 key identifier, never the credential. Honor Retry-After; when remaining daily quota reaches zero, block until at least the next UTC midnight, including on a successful last response. Check before every outbound request. Extend cooldowns with ETag concurrency control so racing responses cannot shorten a block. Existing instances and restarts in the same database share the block; separate development databases discover the shared provider quota through response headers.
2. Cancel remaining/queued page work when any page fails, await cleanup, and propagate the original failure. This prevents continued pagination after 429 or an invalid page and prevents cancellation from replacing the first failure.
3. Set a configurable 45-second refresh budget inside a configurable 60-second offer-read budget, including catalog retrieval. Give ingredient inference its existing separate 30-second budget after source retrieval. Keep requests cancellable and existing daily success reuse/five-minute transient-failure recovery. Rate-limited retries must not call Prej before its reset.
